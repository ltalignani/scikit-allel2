## Project overview

This package provides utilities for exploratory analysis of large scale genetic variation data. It is based on numpy, scipy and other general-purpose Python scientific libraries.

Source: <https://github.com/cggh/scikit-allel2>
Documentation: <http://scikit-allel2.readthedocs.org/>
Download: <https://pypi.python.org/pypi/scikit-allel2>

The package is developed and maintained by the Centre for Genomic Genetics and Healthcare (CGGH) at the University of Cambridge, UK. It runs under python 3.6 to 3.9.13 and is distributed under the BSD license.

However, scikit-allel is incompatible with python 3.10+:
After analyzing the project files, here are the points that explain the incompatibility with recent versions of Python and NumPy:

   1. Using Cython (`.pyx`): The heart of the problem lies in the allel/opt/*.pyx files. These are extensions written in
 Cython, which are compiled in C code for performance reasons. This C code interacts directly with the internal Python APIs
 and NumPy.
       * Incompatibility with NumPy 2.0: NumPy 2.0, recently released, has introduced major, non-backward-compatible changes to its C API. Scikit-allel's Cython code has not been updated for these changes, causing compilation errors or when numpy>=2.0 is installed.
       * Incompatibility with new versions of Python: Similarly, new versions of Python (3.10, 3.11, 3.12+) bring their share of changes to the C API, which can break C code generated by an older version of Cython.

   2. Obsolete automated tests : The continuous integration configuration file (.github/workflows/test.yml) shows that the project is only tested on versions of Python 3.6 to 3.9. There is therefore no automatic check for more recent versions, which explains why these problems have not been corrected.

   3. Non-restrictive dependencies: The requirements.txt and setup.py files specify numpy>=1.17, which authorizes installation of NumPy
 version 2.0. On a recent Python environment, pip will install the latest version of NumPy, thus triggering the
 incompatibilities.

  In summary:
The project is not compatible because its Cython code is obsolete and does not work with the C APIs of recent NumPy versions and Python. The temporary solution would be to force the installation of numpy<2, but a lasting solution would require updating the Cython code and test chain.

The goal of this project is to make scikit-allel2 compatible with recent versions of Python, zarr v.3.1.2 and NumPy v.2.0, while maintaining its functionality and performance.

In addition, you need to rename scikit-allel2 to scikit-allel22, which also means renaming all calls to the module to allel2 instead of allel (import allel2 -> import allel2) and modifying all the implications.

## Key Features

    MILESTONE 1: Update Cython code to be compatible with NumPy 2.0, zarr 3.0 and recent Python versions. 
    The migration guide for zarr 3.0 is available here: https://zarr.readthedocs.io/en/latest/user-guide/v3_migration.html. 
    The migration guide for numpy 2.0 is available here: https://numpy.org/devdocs/numpy_2_0_migration_guide.html. 
    A note for downstream packages authors is available here: https://numpy.org/devdocs/dev/depending_on_numpy.html.
    NumPy's official documentation provides clear instructions. 
    The compatibility with NumPy 2.0 requires five main actions: 
    
    1. Update build dependencies: It is imperative to use Cython 3.0 (or later), NumPy 2.0 (or later) and zarr 3.0 (or later) during the build process. This is configured in the pyproject.toml file.

    2. Adapt Cython code: Cython 3.0 handles most API changes, but you need to check whether there is any custom C code in setup.py which would require manual adaptation.

    3. Adapt zarr code: Ensure that all zarr related code is compatible with zarr 3.0+. The guide is available here: https://zarr.readthedocs.io/en/stable/user-guide/index.html

    4. Update dependencies: Modify pyproject.toml (the single source of dependencies) to specify numpy>=2.0 to avoid installing incompatible versions of NumPy during development and testing. Do not update again already updated allel in allel2 (ensuiring no allel22 will be present in the code).

    Do not change reported issues like https://github.com/cggh/scikit-allel/issues/206 in https://github.com/cggh/scikit-allel2/issues/206. These issues are not related to the update of the package to Python 3.10+ and NumPy 2.0.
    Ensure that all tests pass after making these changes.


    MILESTONE 2: Ensure that the package can be installed and run on Python 3.10, 3.11, and 3.12+.
    - Take into account changes resulting from developments in the zarr module, particularly when importing vcf files in zarr format. The guide is available here: https://zarr.readthedocs.io/en/stable/user-guide/index.html.
    - Modify the continuous integration configuration to include tests for Python 3.10+.
    - Adjust dependency specifications to ensure compatibility with the required NumPy version.
    - Rename the package from scikit-allel2 to scikit-allel22 and update all relevant references in the codebase.
